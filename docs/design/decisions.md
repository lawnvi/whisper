# 设计决策记录

记录为什么这么定，防止以后被同样的问题再带回去。规则本身在 [`DESIGN.md`](../../DESIGN.md)。

改规则前先看这里。用户否决过的方案，除非有新的要求，不要重做。新决策加在对应表格的末尾，写日期和来源。

## 待定

有默认值，没有答复前按默认值做。定下来后移到「已定」，并同步 `DESIGN.md` 和原型。

| # | 问题 | 默认 | 为什么 |
|---|---|---|---|
| 1 | 打开设备默认进哪个分页 | 记住上次，第一次进对话 | 不打断习惯，新用户从最熟悉的开始 |
| 2 | 「流转」这个词留吗 | 分页叫「应用」，动作用「打开」和「送到…」，「流转」只作宣传用语 | 「流转」要解释才懂 |
| 5 | 文件管理器要不要跟随平台 | 骨架全平台一样（照访达做），快捷键用 Ctrl，叫法跟系统，材质跟随系统 | 2026-10-17 用户要求「照访达做」，要确认 Windows 上的外观是否也要这样 |
| 7 | 要不要加协议支持：从接收端发起声音、按设备调音量 | 不加，界面不画 | `DESIGN.md`「真实」原则。AirPlay 式的音量很好用，但要改协议 |
| 6 | 文件和应用要不要回到手机对话页顶部 | 不放，收进设备页，点「⋯」再点一下 | 用户指出长名字会挤。代价是文件和应用多点一下 |
| 10 | 剪贴板历史怎么存 | 只放内存，最多几条，退出就清空，不写数据库。系统标记为敏感的内容（比如密码管理器复制的）不记录 | 现在的 App 没有剪贴板历史，这是新功能。本地存储没有加密，密码不能落盘 |
| 9 | 「下线时不要把他们顶起来」的理解 | 下线不移动行，连上才上移；局域网断了左下角不变高 | 原话可能只指其中之一，要向用户确认 |
| 11 | 平板上要不要加「声音」「键鼠」入口 | 不加。平板的功能和手机一样，没有共享声音和被控 | 现有 App 在这些平台没有这些能力，`DESIGN.md`「真实」 |
| 12 | 三折叠全开时对话和文件要不要并排 | 不并排，和宽屏桌面一样一次一个分页 | 并排会多一种布局。全开是不是常用状态要先看用户怎么用 |
| 13 | 华为的折叠屏（阔折叠、三折叠）要不要支持 | 规则按它们的尺寸验证过，但不算支持。要支持得单独移植鸿蒙版 | 仓库里没有鸿蒙工程。安卓和 iOS 的同类设备直接适用 |
| 8 | 第一步从哪里开始迁移 | 见 [`migration.md`](migration.md) | |
| 14 | 托盘图标要不要表示状态：传输时环变成进度，有请求待处理时多一个小红点 | 先不做，图标一直是静态的圆环 | `surfaces.md`「托盘」写了，代码还没做，2026-11-04 改图标时发现。要做的话三个平台都要换图 |
| 15 | macOS 旧容器的聊天记录读不了时，以后拿到权限要不要再迁移过来 | 不迁移，提示一次，文件留在原处 | 只见过一例，合并两份数据库风险大。提示只在第一次启动出现，之后用户找不回这个入口 |

## 实现时的补充决定（2026-11-02）

| 决定 | 原因 |
|---|---|
| 桌面的「输入地址连接」是一行（`地址` 或 `地址:端口`），没写端口用 10002，开始时填好这台所在网段的前三段 | 原型就是一行；手机的连接设备页仍然分开两个框 |
| 桌面没有单独的连接设备页，要二维码就打开「这台面板」 | 原型的桌面入口只有这台面板，再放一个对话框是重复 |
| 传输列表的颜色：传输中 `accent`，暂停和等待 `warn`，失败 `bad`，完成 `ok` | 只有一种蓝；旧列表用的流转空间配色不进新界面 |
| 「拿回来」结束这台发给对方的那一条流，并通知对方关窗口 | 不改协议，用现有的 `stop` |
| 触控屏上手机和平板是同一棵树（`lib/new_ui/shell/shell_touch.dart`）：列表和内容一直在同样的位置，只有几何变。内容区有自己的导航器，设备和卡片是它的第一页，设置、连接设备、控制页都推到上面 | 折叠和展开不能换路由，草稿和滚动位置才留得住。卡片在第一页里，推页面时就被盖住，回来还在，「收起再打开」不用额外逻辑 |
| 手机回到列表时销毁设备页，和以前弹出路由一样 | 留在列表后面的对话页会继续把消息标记为已读 |
| 触控屏上单击文件夹就进入，单击文件选中，长按是菜单 | 手指没有双击的余地。桌面仍然单击选中、双击进入 |
| 手机和平板的文件访问请求改成弹层（紧凑是底部，有侧栏时居中），Android 在后台时仍然上岛 | 旧的弹窗有另一种蓝和绿色开关。合上和打开时弹层跟着变形，不消失 |
| 配对确认页、设置、连接设备都在内容区打开 | 有侧栏时列表留着。配对页不算离开设备，侧栏不松手 |
| 窗口没有状态栏时，有侧栏就不算沉浸 | 安卓小窗和台前调度的窗口顶上没有状态栏，灵动岛不该因此藏起来。真正铺满屏幕的页面（窗口查看）自己会让灵动岛安静 |
| 传输、状态、短消息的来源手机也装，拷贝里的传输不再单独上岛 | 手机原来只有窗口、拷贝、声音。同一份拷贝不能显示两颗岛 |
| `touchPlatform` 用 `Platform` 而不是 `defaultTargetPlatform` | `flutter test` 里后者总是 android，桌面的外壳测试全会变成触控。和 `isDesktop()` 保持一致 |

## 2026-11-03 试用后的调整

- **设备行的图放进统一的圆角块。** 只用实物图，竖长的手机和横宽的电脑放在一列里怎么调比例都不齐（试过按视觉重量缩放）。渐变块加线条图标最整齐，但丢了「设备是实物」的质感，是备选，用户可以再选。
- **去掉左下角的加号。** 点名字打开的是同一张面板，两个入口做同一件事。
- **应用内的灵动岛只悬浮。** 原来手机上会把页面往下顶 48，用户不要。代价是它可能短暂盖住标题，可以划走。
- **配对数字从说明文字里拿出来。** 它是这张卡片唯一要核对的东西，混在一段话里看不出来。
- **手机的输入框一输入，功能键就收起，只留发送键。** 先试过多行时把按钮整排移到文字下面，真机上文字一换行按钮就跳，短文字左边还空一大块，用户觉得奇怪，已否决。原型的输入框仍是单行 `input`，多行规则以 `surfaces.md` 为准。
- **桌面的输入框最下面一行固定是工具栏（2026-11-04，用户提出）。** 默认两行，最多六行。工具栏一直在，不随文字出现或移动，所以没有上面被否决的跳动问题。
- **截图的工具栏直接在选区旁边，不做成两级（2026-11-04，用户）。** 先做过选区上点「标注」再跳到 Whisper 窗口，用户否决。也不在原生窗口里画：三个平台各写一遍工具和文字输入，样子还做不成这条玻璃工具栏。现在松手时把整屏交给应用自己的窗口，画面不动。窗口必须在画第一帧之前摆好尺寸：Flutter 视图画过一帧后再调大小，主线程要等新尺寸的一帧，实测卡满 1 秒超时（日志 `Resize timed out`），所以每次截图新建引擎（约 0.1 秒），不复用。
- **连接和断开用电源图标，不用文字。** 灰色的「断开」两个字显得简陋，也看不出和「连接」的区别；红底圆块加拔开的插头又太难看，已否决。现在和旁边的信息按钮一样无底，只用颜色区分：蓝色连接，红色断开。
- **附近和离线要一眼分开。** 没配对的壁纸原来是灰的，配对过的附近设备也淡得厉害，都像离线。现在灰色只留给离线，离线的文字也退一档。
- **输入框不放占位文字。** 读屏的说明还在，看得见的提示不要。
- **手机上的导航图标用 `ink`。** 返回、加号、设置都是蓝色时满屏都在强调，看着奇怪。
- **工具栏的图标放进和分页同样的胶囊。** 散放的线条图标和旁边的胶囊分页不是一类东西。
- **没连接时不显示输入框。** 框里放连接按钮、框整块变淡都试过，都奇怪，已否决。
- **手机配对页按核对数字来设计。** 两台设备加一把锁说明在做什么，六位数字每位一格方便逐位对照，按钮都放在手指够得到的底部。
- **灵动岛回到摄像头的高度（已撤回）。** 10 月曾因压住状态栏图标放到状态栏下方，11 月 3 日试过放回去，真机上状态栏的字透过来、摄像头挡一块、点不到，所以又放回状态栏下方。
- **托盘面板的引擎只注册它用得上的插件（Windows）。** `media_kit_video` 用一个静态实例记着顶层窗口原来的窗口过程，第二个引擎再注册一次，主窗口的消息就被转到别的窗口的过程上，`WM_PAINT` 停不下来，一个核心占满。投屏和视频窗口要用这个插件，还是全部注册，**这个风险还在**，没有修。
- **最近的剪贴板包含当前这条，点了不重排。** 原来不含当前这条，点一条它就变成当前并离开列表，上一条顶上来：看起来是同一行的字在来回变，勾也来不及看到。勾只是图标原地变一下再变回去；蓝色大圆底和换文字都太重，已否决。
- **连接诊断改成真的检查。** 原来写死显示「服务没有响应」，连着的设备点开也这么说。
- **桌面菜单跟最长的一行走，最窄 190。** 原来固定 236，短菜单右边空一大块；长文案（西班牙语）又可能被截断。
- **电脑的图看得出系统，不用苹果和微软的标志。** 用户说只能分出桌面和手机。标志最清楚，但 Apple 明确禁止，Windows 要授权，MIT、CC0 只管版权不管商标。试过角标（每行多一个点，杂）和只画系统界面（列表尺寸下 Mac 和 Windows 差不多）。现在同时靠机身颜色、系统界面和 Linux 的企鹅。
- **去掉开关，删旧界面。** 用户：「整理代码，该删的就删了」，先提交 `164bfd8` 作为可回退的版本。结果和没做的见 `migration.md`「第 9 步的结果」。
- **触控设备上进页面只滑入，不再淡入。** 淡入要把整屏连毛玻璃一起先画到一边，每帧一次，小米 17 上进会话第一帧 raster 81 ms。改后滚动时超过 8.3 ms 的帧从约 25% 降到 1% 到 3%，采样的 31 秒里最慢一帧 36 ms（同时改了列表图不生成多级缩放图、提前准备屏幕外内容）。这段采样不确定含不含进页面那一帧，用户试用觉得顺。桌面还留着淡入。
- **毛玻璃留着。** 在同一个包里开关对比：开着 2.8% 的帧超预算，关着 1.1%，差得不多，用户手感也顺。这个数字不含 GPU 时间，样本是 24 秒滚动。
