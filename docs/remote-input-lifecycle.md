# 键鼠共享的会话归属与退出

单设备共享与多设备工作区是两种路由方式，不应各自决定能否占用本机键鼠；本机同一时刻只能有一个输入所有者，多设备工作区内部仍可保留多个对端连接。

## 职责

| 模块 | 负责的事情 |
| --- | --- |
| `RemoteInputManager` | 每个对端的协议会话、输入通道及对应剪贴板资源，并持有本机统一的生命周期实例 |
| `RemoteInputLifecycle` | 决定哪个处理器可以启动，阻止重叠占用，统一取消与清理交接 |
| `RemoteInputCoordinator` | 单设备的发送，以及来自控制端的输入接收、按键翻译和注入 |
| `RemoteInputWorkspaceCoordinator` | 多设备连接、屏幕拓扑和输入路由，不再查询另一协调器的状态来决定启动权限 |
| 原生插件 | 执行采集、注入和释放，仅操作请求中指定的会话 |

生产环境两种处理器使用同一个 `RemoteInputManager.shared`，因此共享同一份输入归属；测试应给两种处理器注入同一个管理器，才能验证模式切换。

## 启动与切换

启动先经过统一的生命周期入口；两种模式同时请求时，仅一个能够取得输入归属，另一个收到已有会话的提示。

正在共享的工作区拒绝被控请求；所有目标离线后，工作区可以保留重连计划，但接受新的控制请求前必须先清除旧计划，因此旧对端重新上线不能把本机抢回控制端角色。

处理器保留各自的展示状态和路由数据，输入归属以生命周期模块为准；不要通过修改界面状态绕过启动入口，也不要在网络收包层另写一套忙碌判断。

## 退出与异步回调

停止立即作废当前任务代次，分离事件回调、清空待注入队列并释放原生键鼠；所有停止请求复用同一次清理，即使通知对端失败也要继续释放本机资源。

新的处理器必须等待旧资源清理完成；若原生启动尚未返回，停止操作先释放当前输入，迟到的启动再按原会话编号执行回滚，回滚完成后才允许新处理器占用键鼠。

连接、边缘释放、路由更新和粘贴准备等异步操作在返回后核对任务代次，失效操作不得重新启用状态或覆盖新会话的数据。

每个对端的停止、断线、拒绝、错误与移出工作区共用资源清理流程；`stopSession` 先将协议会话标记为停止，再关闭通道和清理剪贴板，并按会话编号合并重复清理。

## 验证与边界

[生命周期回归测试](../test/remote_input_lifecycle_test.dart)覆盖同时启动、控制与被控互斥、清理期间交接、迟到原生启动回滚、旧边缘回调、重连计划取消、剪贴板清理和停止通知失败；现有测试继续覆盖输入顺序、队列上限和多屏路由。

这次调整不改变线上协议或平台原生接口，已发布客户端仍使用原有的握手与输入包；自动化测试与构建检查不替代双向截图、粘贴、跨屏和休眠唤醒的实机验收。

2026-09-11 验证：静态分析通过，全量测试 1641 项通过、3 项跳过；macOS arm64、x86_64 Release 构建及现有证书签名检查通过，Linux x86_64 的 55 项相关测试和 Release 构建通过，同步的 8 个源码与测试文件校验一致。

本轮没有执行 Windows 原生构建、跨机桌面操作验收或替换三台设备正在运行的应用；上述结果针对新代码与构建产物，不代表完整实机验证。

慢速粘贴的输入排队体验、临时图片的长期回收是独立的后续事项，不由会话归属模块代管。
