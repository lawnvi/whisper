# 2026-11-12 网页传输：小米 17 上的 Chrome

接着 [`2026-11-12-web-transfer-trial.md`](2026-11-12-web-transfer-trial.md)，第一次用真的手机浏览器。这台是 Mac 上的调试版（Wi-Fi，192.168.41.7，服务器在 10004）；访客是小米 17（HyperOS，Android 17）上的 Chrome 151，深色模式，连 2.4 GHz 的 11n（协商 144 Mbps）。用户在两边动手，我用 adb 截图、点按，看这台的数据库。

## 通过的

| 场景 | 结果 |
| --- | --- |
| 打开地址 → 4 位数 → 在 Mac 灵动岛上点「允许」 | 用真的窗口点的（之前只看过离屏渲染），进了对话 |
| 双向文字 | 都到 |

## 发现的问题

- **Chrome 拦下载。** 点下载后 Chrome 弹出「无法安全地下载文件」（选项是「舍弃」和「保留」）。Chrome 对所有 http 下载都这样拦，局域网地址也一样。那次 dmg 下到 127 MB 就断了，这台写「等待重连」。改法：在 Chrome、Edge、Opera 上（iOS 除外），点下载后页面提示 5 秒要选「保留」。
- **选文件的系统框名字误导人。** 点「+」后系统给的是「拍照、录像、照片和视频」。「照片和视频」其实是小米的「安全访问」文件选择器，切到「浏览」能看到文档、压缩包、下载、我的手机，选什么文件都行。用户看到这几个名字，以为只能选照片和视频。
  - 原因：在 HyperOS 上，「选任意文件」（`GET_CONTENT */*`）优先级最高的处理者是系统的 `com.android.photopicker/.hyper.HyperMainActivity`，它在选择框里的名字就叫「照片和视频」。
  - 用测试页试了 6 种写法：不写 `accept`（单选、多选各一次）、`*/*`、`*`、混合几种类型、`application/octet-stream`。弹出来的选择框都一样，网页改不了这个名字。
  - 写 `accept="image/*,video/*"` 时会跳过选择框，直接进小米的相册网格。但那样就只能选照片和视频了，而且「原图」默认没勾。没有改，只写进了使用指南。
- **数字页说明断在词中间**（「核对这 / 个数字」）。改成中文按空格和标点换行。
- 用户觉得**顶栏不好看**（灰色实底、亮蓝头像、文字的语言按钮）。改成像 iOS「信息」那样：顶栏没有实底，按钮是浮着的玻璃，头像是纯色的灰，名字放在小胶囊里。
