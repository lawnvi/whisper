# 2026-11-12 网页传输实测

这台是 Mac 上的调试版（macOS，局域网地址 192.168.41.3，服务器自动用了 10004，10003 被正式版占着）。访客是同一台 Mac 上的 Chromium（Playwright 驱动，iPhone 13 和 1280×800 桌面两种模拟），走真实的局域网地址，不是本地回环。这台一边的操作（允许、拒绝、发文字和文件、断开）通过调试版的 VM service 调 `WebTransferCoordinator`，界面截图用离屏渲染。

## 通过的

| 场景 | 结果 |
| --- | --- |
| 打开网页 → 4 位数 → 这台允许 | 两边数字一致，允许后进对话 |
| 双向文字、表情 | 都到，网页的文字送达后变实 |
| 这台发图片和文本文件 | 网页显示预览；下载的内容和原文件逐字节一致，文件名正确 |
| 网页传 20 MB | 1.3 秒，落盘内容一致 |
| 空文件、`报告:最终版?<v2>.txt`、230 个字符的名字 | 都送达；名字变成 `报告_最终版__v2_.txt`，长名保留 `.pdf`，重名加 `-1` 不覆盖 |
| 粘贴一张图片到桌面网页的输入框 | 先出现在输入框上方，回车后发出 |
| 网页取消正在传的文件 | 两边都是「已取消」，没留临时文件 |
| 面板没开时打开网页 | 显示「还没有打开网页传输」；这台打开后 1 秒内自动出数字 |
| 拒绝 → 再试一次 | 重新出数字，这台只有一个请求 |
| 等确认时刷新网页 | 修复后还是同一个数字、一个请求（修复前会换数字） |
| 两个访客同时在线 | 都在线，互不影响 |
| 网页离开时这台发文字 | 网页回来后补上 |
| 这台断开 → 网页「重新连接」 | 网页显示「MacBook Air 结束了连接」；重连要这台再确认，历史还在 |
| 网页刷新 | 回到对话，历史都在 |
| 这台 App 退出再打开 | 修复后网页显示「已断开」和「重新连接」（修复前一直「正在重新连接」） |
| 语言切换 | 整页换语言，刷新后还记得 |
| 页面脚本错误、CSP 拦截 | 没有 |

网页在 iPhone 13、360 宽的安卓、iPhone 横屏、iPad、1280×720、1920×1080、2560×1440 下截图看过（Chromium）。

## 没测的

- **真的手机浏览器。** 小米 17 这次在 adb 里一直离线，没用上。iPhone 的 Safari、安卓自带浏览器、微信内置浏览器都没在真机上开过。本机 Playwright 的 WebKit 版本对不上，Safari 只看过 Chromium 的模拟。
- **Android、Windows、Linux 当这台。** 只在 macOS 上跑过。Android 上从「文件」选的文件是 `content://`，下载走另一条读法，没在真机上走过。
- **灵动岛上点允许、面板翻面、允许后面板收起并打开对话** 这几步在真实窗口里没点过（调试版窗口在后面，不出帧），只看了离屏渲染。
- 断网 10 分钟后结束、锁屏后回来续传、几 GB 的大文件。
