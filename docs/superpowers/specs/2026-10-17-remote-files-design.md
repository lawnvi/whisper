# 设备文件：像同一台电脑上的两个文件夹一样传文件

## 目标

用户原话（2026-10-17）："在本机打开已连接其他设备的文件管理器，这样传文件时就可以像是一台电脑上把文件/文件夹复制到这台电脑上的另一个目录了……文件管理器这个可以好好想想怎么做，做好了体验不亚于流转这个能力。"

- 在本机直接浏览一台已信任设备的文件：位置、文件夹、缩略图、大小、时间；
- 复制、粘贴、拖放：对方 → 本机、本机 → 对方的任意文件夹，文件和文件夹一样；
- 新建文件夹、重命名、删除（进废纸篓）；
- 入口在每台设备自己的页面上（和"流转"并排），不在主界面搜索框后面。

## 不做（第一版）

- 两台远端设备之间直接复制（A 上操作 B → C）；
- 编辑远端文件后自动回写；
- 系统文件管理器集成（Finder 侧栏挂载、安卓 DocumentsProvider）。架构上留位置，见"以后"。

## 用户看到的样子

### 桌面（照访达做，2026-10-17 用户要求重做）

- 一个窗口管所有设备，像访达：
  - 左侧边栏分两组："个人收藏"是本机的桌面、文稿、下载等；"位置"是本机和每台已连接、已信任的设备。正在浏览的设备下面展开它自己的常用位置；
  - 顶部工具栏：后退 / 前进、当前文件夹名、列表 / 图标切换、新建文件夹、更多（显示隐藏文件、刷新）、搜索（只筛当前文件夹）；
  - 列表视图有名称、修改日期、大小、种类四列，点列头排序，隔行浅底，选中是系统蓝；窗口窄时依次收起种类、大小、日期；图标视图显示图片和视频缩略图（视频带播放角标）；
  - 底部是路径栏（可点）和状态栏（"已选择 2 项，共 9 项"、拷贝进度）。
- 拷贝只在本机和另一台设备之间：
  - 拖到侧边栏的位置、列表里的文件夹或空白处；
  - ⌘C / ⌘V，跨设备也行；
  - 从访达拖进来。
- 同一台设备内拖放不接受（不做移动）。
- 第一次点开别的设备时，内容区写"请在 X 上点'允许'"，侧边栏那台设备转圈。
- 键盘：方向键选择、⌘A、⌘⌫ 删除、回车重命名（Windows/Linux 回车打开，F2 重命名）、⌘↑ 上一级、⌘↓ 打开、⌘[ / ⌘]、⌘⇧N、⌘F。
- 重命名就地编辑，默认选中扩展名前的部分；新建文件夹先建"未命名文件夹"再进入重命名。

### 手机（照"文件"App 做）

- 首页"浏览"：分组列表"位置"（本机和其他设备，带等待 / 拒绝 / 离线说明）和"个人收藏"；
- 进入文件夹从右侧推入，大标题下写设备名，有搜索框；返回按层级回到"浏览"；
- 点文件弹出操作表：拷贝到…、重命名、删除；"选择"后底部操作条做同样的事；
- "拷贝到…"回到"浏览"让用户挑位置，底部条显示"拷贝到这里"；同一台设备或两台都不是本机时按钮不可用，并写明原因；
- 窗口宽度不到 700 时桌面也用这套布局。

### 动效

- 拖放时，被拖的条目缩成带数量角标的一叠；放下后，这叠沿弧线落进目标文件夹，目标文件夹轻轻弹一下；
- 打开文件夹：内容从被点的条目位置展开（共享元素），返回时缩回去；
- 两栏的连接处在拖动时亮起，表示"可以放到这台设备"。

## 权限和安全

- 只对已配对、已信任的设备开放（和流转相同）；
- 对方第一次访问时，被访问的设备弹出确认："‹设备› 想浏览你的文件"——允许一次 / 始终允许 / 拒绝。选择按设备记住，可在该设备的设置里改；
- 开放范围：整个主目录（安卓：内部存储）；
- 路径一律在服务端解析成真实路径后检查是否仍在允许的根目录内，符号链接不跟到根目录外，拒绝 `..`；
- 删除默认进废纸篓（macOS `trashItem`、Windows 回收站、Linux freedesktop Trash；安卓没有废纸篓，先二次确认）；
- 日志里不写路径和文件名（沿用现有隐私日志规则）。

## 架构

### 为什么不走聊天通道

流转这次踩过的坑：一次发出约 100 条控制消息（图标请求）就把聊天通道挤断。文件列表和缩略图更多更大，所以文件浏览单独走一条认证过的媒体路由。

### `/fs` 路由

- 和 `/window`、`/audio` 一样：聊天通道上先发控制消息拿一次性令牌，再拨 `/fs` WebSocket，帧加密，关压缩；
- 请求-应答，每个请求带 id，服务端限制并发（比如 8 个），客户端也限流；
- 请求类型：
  - `roots`：可访问的位置列表；
  - `list(path, cursor)`：分页（每页 500 条），返回名称、类型、大小、修改时间、是否隐藏；
  - `stat(path)`；
  - `thumbnail(path, size)`：图片、视频、PDF 缩略图（macOS QuickLook，安卓 MediaStore/ThumbnailUtils），两端都缓存；
  - `mkdir`、`rename`、`trash`、`delete`；
  - `read(path, offset, length)`：只用于快速预览。

### 复制复用现有传输

- **对方 → 本机**：本机发"请求文件"（路径列表 + 本机目标文件夹），对方用现有的多文件/文件夹传输把它们发过来，本机自动接收、写进指定文件夹。现有协议是发送方发起，这里加一个由接收方发起的请求，对方校验路径后照常发 offer；
- **本机 → 对方**：现有发送流程加一个"目标文件夹"字段，对方校验它在允许的根目录内，存到那里而不是默认下载目录；
- 续传、校验、文件夹流（`sha256-folder-v1`）、安卓并行写入池都直接沿用。

### 代码位置（草案）

- `lib/remote_files/`：`fs_protocol.dart`（请求/应答格式）、`fs_host.dart`（被访问端，路径校验、列表、缩略图）、`fs_client.dart`（访问端，分页、缓存、限流）、`fs_permissions.dart`；
- `lib/page/remote_files/`：`files_model.dart`（设备、位置、历史、选择、拷贝）、`files_desktop.dart`（访达式窗口）、`files_phone.dart`（"文件"式手机界面）、`files_icons.dart`（文件夹 / 文稿图标、种类和日期文字）；
- 原生：缩略图（macOS QLThumbnailGenerator、安卓 ContentResolver.loadThumbnail），拖放（macOS NSFilePromiseProvider 往访达拖出）。

## 分阶段

1. **F1 只读浏览 + 复制到本机**：`/fs` 路由、权限确认、列表、缩略图、对方 → 本机复制；桌面双栏和手机单栏的基本界面。
2. **F2 写入**：本机 → 对方任意文件夹、新建文件夹、重命名、进废纸篓、拖放、访达拖入拖出、快速预览。
3. **F3 打磨**：搜索、最近文件、多设备位置选择器、动效细节、大目录性能（万级文件）。

## 实现情况（2026-10-17）

已实现 F1 和 F2 的主体，真机（MacBook Air ↔ 一加 8）验证过：

- 协议：新消息类型 `MessageEnum.FileBrowseControl`，能力位 `remoteFilesV1`（随协议 12 一起，12 尚未发布）。复用控制会话的方向和身份校验；被访问端只对已信任设备开放，问用户期间不占用该对端的接收队列。
- 被访问端：`lib/remote_files/fs_paths.dart` 线上只用"根目录 id + 相对路径"，解析成真实路径后必须仍在根目录内（符号链接不出界），重命名和删除对符号链接本身操作；`fs_host_files.dart` 列表（文件夹在前、自然排序、500 条一页）、新建、重命名、删除；`fs_platform.dart` 废纸篓（macOS `trashItem`、Windows 回收站、Linux freedesktop）和缩略图（macOS QuickLook、安卓 ThumbnailUtils）。
- 复制：两个方向都是普通的可续传传输，完成后由 `fs_placement.dart` 挪进选定的文件夹，并改写数据库里那条传输和消息的路径，安卓上让媒体库重新登记。实测：一加 → Mac 的照片进了指定文件夹且保留修改时间，Mac → 一加的文件进了新建的文件夹，没留在"下载"里。
- 权限：被访问端弹窗"允许这一次 / 始终允许 / 拒绝"，"始终允许"按设备记住（`remote_files.always_allowed`），一分钟不答算拒绝；手机在后台时发通知，桌面把窗口提到前面。
- 界面：会话页顶栏"文件"按钮打开并直接定位到那台设备。第一版是左右两栏；用户觉得不好看后，按访达（桌面）和"文件"App（手机）重做，见上面"用户看到的样子"。重做后的界面只在测试里渲染截图检查过，还没在真机上看过。

已知问题和待办：
- 复制会出现在聊天记录里（是普通传输），要不要隐藏待定；
- 拷贝的文件会放进系统剪贴板，让访达等应用能粘贴；这些文件已经标记为"自己写的"，开着键鼠共享时剪贴板同步也不会把它们发给对方；
- Windows、Linux 没有缩略图；
- 快速预览、框选还没做；
- 手机会话页顶栏图标多，标题被挤短，待调整。

## 拖出和粘贴（2026-10-18）

- 拖出：macOS 和 Windows 上条目走系统拖放，能拖进访达和资源管理器。本机的文件直接给路径；对方的文件放下后才开始取，取完写进访达给的位置（macOS 是文件承诺，Windows 是虚拟文件），进度显示在访达或资源管理器里，在那边取消会停掉这次传输。窗口里的拖放也改走系统拖放，靠拖动项里带的条目信息认出是自己的。
- 限制：对方的文件夹拖不出去（系统只接受单个虚拟文件），只能在窗口里拖或复制粘贴；Linux 没有虚拟文件，仍是窗口内拖放，拖不到 Nautilus/Dolphin。拖出的文件会先完整落到本机临时目录再写过去，大文件要多一次本地写入。
- 粘贴：复制对方的文件后会先取到暂存目录供访达粘贴；在 Whisper 里粘贴时，还在路上的那部分直接改投到粘贴的文件夹，不用等取完再复制一遍；已经取完的从暂存目录复制过去。
- 粘贴到其他应用（2026-10-18 第二次）：
  - Windows：复制对方的文件后，剪贴板上直接放虚拟文件（`FileGroupDescriptorW` + `FileContents`），不先取回。在资源管理器里粘贴时才开始取，资源管理器显示进度。实测从 Ubuntu 取 300 MB：粘贴后约 1 秒出现文件，14 秒完成，SHA-256 一致。对方的文件夹仍先取到暂存目录。
  - macOS：访达只粘贴已经在磁盘上的文件，不接受剪贴板里的文件承诺（拖放才接受），所以仍要先取完；想马上开始就拖进访达。Linux 的文件管理器同样只认已有文件。
  - Whisper 自己的窗口里：⌘C 后马上点侧边栏换个文件夹 ⌘V，粘贴立刻开始，接管正在暂存的那次传输（界面测试覆盖）。
- 复制后再粘贴（2026-10-19 第三次）：
  - 复制对方的文件时，只有总共不超过 32 MB 的文件会马上取回，好让访达和 Linux 文件管理器能直接粘贴。更大的文件和文件夹不再预先取回：在 Whisper 里粘贴时才开始传，状态栏提示"已复制，粘贴时才开始传输"。Windows 上的文件仍以虚拟文件放进剪贴板。
  - 拖到访达或资源管理器时的拖拽图按自己的大小排版。原来套用整行的约束，被拉成和那一行一样宽的长条。
