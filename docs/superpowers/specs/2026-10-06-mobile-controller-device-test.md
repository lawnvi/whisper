# Android → macOS 本机配对测试

日期：2026-10-06。设备：USB 调试连接的 MI 6（Android 13、ARM64）和本机 Intel Mac。USB 用于安装及驱动手机界面；Whisper 控制流量走双方局域网地址。

## 环境

- 安装本分支 ARM64 debug APK，保留现有应用数据；Mac 启动本分支已编译的 debug 应用。
- 两端使用 Flutter 3.44.9 调试连接，Mac 热重载最新 Dart 收尾修改。未重新执行完整双端构建。
- 恢复 Mac 构建脚本裁剪但尚未重新签名的七项 Flutter 包资源后，现有构建包通过 `codesign --verify --deep --strict` 并成功启动。这验证的是 Xcode 已生成的 ad-hoc 开发构建；稳定证书签名脚本仍未验证。未创建、导入、替换证书、密钥或 keystore。
- 运行态检查：协商协议 11，认证批准与提交均为 true；日志确认双向信任、手动 offer/accept、macOS 接收端 active。
- 使用 ADB 操作手机界面，在独立 Cocoa `NSTextView` 测试窗口记录系统鼠标、按键、修饰键和文本事件。日志与辅助工具仅存于本机 `/tmp`，没有上传。

## 已验证

| 检查 | 实际结果 |
| --- | --- |
| 虚拟键盘 Q/W/E | 收到对应 Mac 键码 12/13/14 的按下和抬起 |
| Shift+A 后接普通 S | A 带 Shift，随后修饰键释放，S 的 flags 为 0 |
| Unicode 文字、emoji 和换行 | 手机草稿 `Whisper 中文测试 🙂\nsecond line 123` 提交后，Mac 测试窗口内容逐字相同；换行有独立 Enter 按下/抬起，手机收到确认并清空草稿 |
| TextEdit 文本 | 收到英文测试文本及换行；未完成三类目标应用矩阵 |
| 连续单击/双击 | 20 次单击和 20 次双击，共 60 次 mouseDown、60 次 mouseUp；40 个 clickCount=1、20 个 clickCount=2 |
| 右键 | rightMouseDown、rightMouseUp 成对到达 |
| 触控板单指移动 | 手机横向移动 180 个物理像素，Mac 光标相对移动 60 个逻辑像素 |
| 触控板双指滚动 | Mac 收到 wheel 事件；未产生点击 |
| 传感器接入 | Android sensorservice 确认陀螺仪、重力传感器以目标 10000µs 周期注册，切出体感模式后注销 |
| 静置漂移 | 灵敏度为设备当前的 1.75 倍；第一轮记录约 20 个逻辑像素位移，不能判定合格。调用应用校准后，在用户确认暂停操作的复测中，按住移动区 10 秒，光标从 (600,450) 到 (600,450)，位移 0 |
| 后台清理 | 按住手机左键时 Mac 系统按钮状态为 1；手机回到桌面后变为 0，回到控制页显示“已就绪”，没有自动开始 |
| 心跳超时清理 | 按住左键后，用调试器暂停 Android 主 isolate，阻断输入和心跳；Mac 约 1.925 秒后释放左键。恢复 isolate 后手机回到“已就绪” |
| 熄屏清理 | 按住左键后让手机熄屏，Mac 按钮状态恢复释放 |

Unicode 测试使用 Android 辅助功能给草稿输入框设置测试文本，然后点击页面的发送按钮。它验证草稿提交、加密传输、Mac Unicode 注入和回复流程，不等于完整验证每种手机输入法的组词与提交行为。

## 未通过验收或未覆盖

- **真机组合拖拽仍未验收。** 自动合成“一个触点按住左键、另一个触点移动触控板”的 20 轮测试收到成对的按钮事件，但没有收到拖拽位移；单指移动及双指滚动单独正常。诊断看到第二触点存在全局 PointerDown，但未进入触控板 Listener。尚未区分自动化手势与真机交互问题，不能将这 20 轮计为拖拽通过。
- 新增组件测试验证相同双触点顺序，在 Flutter 测试环境内能产生按下 → 相对移动 → 抬起；这不能替代上述真机验收。
- 空中转腕方向、空中拖拽、舒适度及高帧率录像 p95 延迟尚未验证。静置复测只代表本机本次校准与姿态，不是漂移性能保证。
- 浏览器、终端、全部功能/导航键、长按重复、Command+V 剪贴板保持、真实 Wi-Fi 中断、多显示器、横屏/主题/大字号的真机矩阵未全部重跑。
- 心跳测试通过暂停发送端模拟无输入/心跳，并未切断手机 Wi-Fi。
- 额外观察：熄屏测试后，若在手机仍处于熄屏/后台状态时用 ADB 冷启动，现有 KeepAliveForegroundService 会抛出 Android 13 的 ForegroundServiceStartNotAllowedException。手机随后要求本机 PIN 或指纹解锁，因此未验证解锁后的恢复；本轮未修改该后台启动异常路径。
