# Android → Ubuntu 连接失败修复

## 原因和修复

Ubuntu 已通过双向信任校验、启动系统注入并回复 accept，但手机随后尝试连接 `192.168.31.20:0/input`。主聊天连接由电脑主动建立时，手机只知道远端地址；该连接的来源端口不能作为电脑监听端口，而身份档案也不传输端口。因此在没有已知监听端口的情况下，独立键鼠通道启动失败。

手动模式 accept 现在通过已有加密控制通道携带可选 `transportPort`，取自实际运行的 HTTP 服务端口。手机使用该端口及当前认证连接的电脑地址建立 `/input` 通道。字段仅在手动 accept 输出；解析拒绝非整数、超出 1–65535 范围和其他动作中的端口。旧接收端省略该字段时仍使用现有已知端口。身份档案、协议 9/10 和桌面边缘模式的输出保持原样。

复测还发现 Linux portal 滚轮将非零位移和 `finish=true` 合并到同一次调用。Mutter 将其解释为结束事件，实际送到应用的位移为零。现在先发送位移，再发送零位移的结束事件。

修改文件：`remote_input_protocol.dart`、`remote_input_coordinator.dart`、`svrmanager.dart`、Linux `remote_input_plugin.cc`，及对应协议、会话、原生源码回归测试。

## 验证

Flutter 3.44.9；无依赖、锁文件或签名资产变更。

- 针对性测试 25 通过：未知端口 0、过期端口、旧接收端回退、字段复制、端口范围和非法动作。
- `flutter analyze --no-pub`：无问题。
- 全量测试 1,726 通过，3 跳过；随后 Linux 滚轮源码回归测试 20 通过。
- Android ARM64 debug 构建安装成功；Ubuntu debug 构建成功并启动。Ubuntu 继续使用上一份接收端报告记录的临时依赖路径与编译警告选项。
- 手机实际 UI 连接 Ubuntu 成功，双方均进入 active。使用手机合成触摸、生产加密 `/input` 通道和 Ubuntu 独立 GTK 测试窗口核对：单指移动、左键、右键、双指右击、两次拖拽均收到对应事件，鼠标按下与抬起成对。
- 直接按键 A、Enter、B 得到 `a\nb`；Ctrl+A 收到 Control 与 A 的按下/抬起。
- 滚轮修复前只收到 28 个零位移结束事件；修复后收到 29 个非零滚动事件及对应结束事件，GTK 累积纵向滚动量约 8.003 单位。
- 已录制最终手机键盘过渡并检查抽帧：内容淡出后切换方向，再显示新布局。键盘进入横屏、返回竖屏时控制会话均保持 active。

端口 0 和非默认端口路径由回归测试验证；这轮重新连接后的手机档案已有 10002 端口，真机结果不冒充“缓存仍为 0”的现场重测。主观体感手感与高帧率延迟未在本轮测量。

测试结束后停止手机控制、退出 GTK 测试窗口、恢复 USB 亮屏设置，Ubuntu 正常 Whisper 保持运行。原始测试事件与过渡录像保存在本机 `/tmp/whisper-phone-linux-events.jsonl`、`/tmp/whisper-transition-final.mp4`。
