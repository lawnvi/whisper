# 手机空中鼠标与键盘可行性探索

日期：2026-10-06

分支：`codex/mobile-air-mouse-spike`，从当前 `dev` 创建。

状态：完成代码路径调查；尚未实现手机控制原型，也未验证传感器手感或端到端延迟。

## 目标与初步结论

让手机在同一局域网内控制已建立信任关系的电脑：在空中小幅转腕移动光标，屏幕按钮完成点击和拖拽，手机输入法完成文字输入。无需水平桌面。

从现有代码结构看具备实现条件：可复用认证、加密输入通道、输入队列和电脑端鼠标/按键注入。需要新增手机输入源、显式手动控制会话和已确认文字的提交路径。现有桌面边缘穿越会话不能直接作为手机控制会话使用。

本轮探索只新增本文档，不变更应用行为、协议、依赖或签名配置。以下方案及验收指标用于后续原型，均不代表已经验证。

## 原型交互范围

- 首个端到端组合为 Android → macOS；Windows 和 Linux X11 的接收适配另行验证，iOS 暂不纳入首轮。
- 从当前已连接电脑进入独立的手机控制页面，手动开始、手动停止；同一时间控制一台电脑。
- 按住移动区时采集转腕动作；松手停止发送移动，重新按下不补发暂停期间的动作。
- 左右键按钮产生按下/抬起事件。左键按住期间允许转腕拖拽，松开结束拖拽。双击沿用系统双击语义。
- 提供触控板作为精细定位和无陀螺仪设备的替代方式；提供触摸滚动区，体感滚动作为后续实验。
- 点击键盘按钮弹出手机输入法，暂停体感移动。原型先使用本地输入框和显式“发送文字”，确认中文、emoji、多行文本可靠后再评估逐次提交输入。
- Enter、退格、Esc、Tab、方向键与常用组合键独立发送。发送文字前可在本地编辑草稿，发送后对电脑输入框的修改通过远程按键完成。
- 离开页面、进入后台、锁屏、连接断开、停止控制时清理传感器订阅并释放所有远程按键和鼠标按钮；重新连接后需手动开始。

## 建议的接入方式

### 手动控制会话

扩展现有会话类型，明确区分桌面边缘穿越和手机手动控制；沿用已有 manager、coordinator、认证和生命周期边界。具体字段名在实现协议时确定。

- 双方通过新的能力标识协商手动控制。旧版本未声明能力时，不允许发送新模式请求；缺省模式继续保持旧有桌面语义。
- 手机只发布实际支持的输入源能力，不发布输入接收能力或虚构显示器拓扑。
- 手机输入事件从 Dart/传感器输入源进入同一有序发送路径，不调用桌面 `startCapture`。
- 接收端显式关闭进入边缘定位和反向穿越释放，保留当前光标位置与原生按钮状态管理。macOS、Windows、Linux 各自验证该模式，不通过伪造 `layoutEdge` 绕过限制。
- 延续双向信任、当前认证连接、会话身份校验和输入所有权检查。电脑和手机均显示正在控制状态及停止入口。
- 移动、按钮、滚动、按键和文字操作保持顺序；队列溢出或注入失败时结束会话并释放输入，避免遗留按下状态。

### 体感映射

使用陀螺仪角速度和单调时间间隔计算角度增量，再映射为相对光标增量。处理重力方向、手机朝向及屏幕旋转，避免把机身某个固定轴直接当作所有握姿下的水平轴。

原型先固定竖屏，测量自然遥控器握姿下的坐标映射；横屏和大幅改变握姿列为后续扩展。使用实测数据选择静止偏置校准、死区和滤波参数，保留小数位移。无效数值、非递增时间戳和长时间采样间隔应丢弃并重置积分状态。

初始可尝试约 100 Hz 采样、最多 60 Hz 发送；这些仅是实验起点。合并移动增量时保留其与按钮事件的先后边界，不跨越点击或拖拽起止。点击附近的短时运动抑制要单独测量，避免造成拖拽无法启动。

不以加速度双重积分追踪手机的空间平移位置。首轮验证的是小幅转腕操作，实际方向、静止漂移、延迟和疲劳程度均需要真机测试。

### 手机键盘与中文

将普通文字提交与物理按键分开。手机输入法的组合文本保留在本地，仅发送用户确认后的文字；不把拼音组合过程逐键注入电脑。

第一版先验证显式发送草稿，避免自动纠错、组合区变化、删除和光标位置同步混在一起。后续若支持逐次提交，需明确 `TextEditingValue.composing`、替换、删除及 emoji 字素边界语义，不能仅对每次 `onChanged` 做字符串追加。

建议评估独立、可协商的文字提交操作，携带会话标识和操作标识，并提供结果确认及会话内去重。断连后不自动重发未确认文字，以免重复输入。

macOS 先评估原生 Unicode 注入的应用兼容性；剪贴板加粘贴可作为备选，但必须处理写入完成后再粘贴的顺序、全局剪贴板副作用及并发改动。不能把现有普通剪贴板消息与 `/input` 上的粘贴按键并行发送后假定顺序可靠。Windows 与 Linux 文字注入策略独立验证。

## 分阶段验证

1. **无传感器的手动控制链路**：手机触控板发送移动、左右键、拖拽、滚轮，电脑从当前光标位置响应。先确定会话模式、能力协商和原生边缘行为正确。
2. **体感输入**：加入 Android 采集与纯 Dart 映射器，测量静止漂移、转腕方向、抬手暂停、点击偏移和端到端延迟，与触控板对照。
3. **文字及特殊按键**：验证中文、英文、emoji、多行文字、Enter/退格和组合键；文字提交与后续按键严格按序。
4. **异常与平台回归**：验证后台、锁屏、失联、权限不足、传感器缺失、旧版本对端和桌面工作区冲突；再扩展 Windows/Linux 接收端。

## 验收方法

下表是原型目标，尚无实测结果。

| 场景 | 验证方法与通过条件 |
| --- | --- |
| 基础移动 | 自然握姿左右/上下转腕方向正确；调整握姿后重新按住无跳变；到达屏幕四边仍保持控制。 |
| 静止与精度 | 固定手机并按住移动 10 秒，目标累计漂移不超过 5 个桌面逻辑像素；手持时重复选择小目标，记录命中率与抖动。 |
| 点击与拖拽 | 连续 20 次点击/双击和 20 次拖拽，无遗漏抬起或残留拖拽；点击运动抑制不会阻断拖拽。 |
| 响应速度 | 同一局域网通过高帧率录像测量物理转动到光标变化的端到端延迟，暂定目标 p95 小于 100 ms；另记传感器与队列耗时，不用两台设备未同步的时钟相减。 |
| 暂停与断连 | 松手停止新增移动；后台、锁屏和断连后不持续移动，电脑释放所有按钮/修饰键；恢复后不自动接管。 |
| 文字输入 | 原生编辑器与浏览器输入框内，中英文、emoji、多行文字均不重复、不漏字；取消组合文本不发送；提交文字后 Enter 顺序正确。 |
| 权限与兼容性 | macOS 权限不足时给出可恢复状态；无传感器可用触控板；旧版本电脑不进入未协商模式。 |
| 桌面回归 | 现有边缘穿越、回切、工作区互斥及断连释放测试仍通过；测试不能把桌面边缘语义改成手机语义。 |
