# 电视投屏（DLNA）

在 macOS、Windows 或 Linux 的“设置 → 连接与传输”中开启“电视投屏”，然后在同一局域网的视频 App 中选择这台电脑。广播名称直接使用设备昵称或系统电脑名称；旧版保存的通用 Mac 型号名称会改用当前系统名称，已明确设置的昵称会保留。修改昵称后，接收名称随之更新；发送端可能需要重新搜索以刷新缓存。手机不需要安装 Whisper，也不需要配对或建立聊天连接。

## 开关与播放

开关默认关闭，并保存上次选择。关闭开关会停止广播、关闭控制服务并结束视频；退出 Whisper 同样释放资源，但保留开关偏好。网络不可用或启动失败直接显示在设置项下方，排除问题后关闭再开启即可重试。

每次开启接收后，同一来源首次发起播放或控制操作时，会显示来源 IP 和确认提示；提示显示后倒计时 5 秒自动允许，也可以立即允许或拒绝。确认之前不会加载视频或改变正在播放的内容、音量。拒绝后，该来源在本次开启期间不能继续控制，也不会反复弹窗；需要重试时关闭再开启接收。决定不永久保存，来源 IP 也不等同于已验证的设备身份。手机取消待确认投屏或关闭接收会取消倒计时；界面无法展示提示时，不自动放行。

视频在 Whisper 的独立投屏窗口中播放，主窗口仍可继续聊天、传文件和使用其他协作功能；两个窗口属于同一个 Whisper 进程，不会启动第二个应用或 `ffplay` 等外部程序。手机和电脑控制同一个播放器，支持播放、暂停/继续、停止、定位、音量和静音；暂停后继续播放不会重新加载视频。静音期间调整音量会保留设置，取消静音后应用该音量。播放器出错时返回控制失败或播放错误状态，不把失败操作报告为成功。

关闭播放界面只结束当前视频，电视投屏开关仍保持开启，可以接收下一次投屏。仅有接收服务时不创建解码器；开始播放才创建，停止播放或关闭服务时释放。

全屏时，标题和控制条在 3 秒无操作后淡出，鼠标移动或键盘操作会重新显示；拖动进度、音量或使用 Tab 操作控件时保持可见。窗口模式始终显示控制条，音量轨道随窗口宽度扩展；空格控制暂停/继续，F 切换全屏，Esc 先退出全屏，再结束播放。

## 接收范围与结构

DLNA 接收的是手机 App 提供的媒体地址，电脑直接读取并播放，不额外转码。视频平台提供什么清晰度、是否允许投屏以及内容是否受保护，仍取决于发送端和平台。当前不接收系统屏幕镜像；之前的路线与实际效果见 [AirPlay / Wi-Fi Direct 实验记录](2026-09-17_cast-experiments-report.md)。

Dart 实现 SSDP 发现、设备描述、控制请求与事件订阅；`CastPlayer` 串行执行手机和本机指令，`MediaKitCastEngine` 负责实际播放并回传进度、时长和状态，`CastPlaybackHost` 在 Whisper 窗口显示画面。SOAP 控制等待播放器操作返回后再确认成功，避免只有状态字段改变、画面或音量却不变。

广播与设备描述使用选定的局域网网卡，优先避开代理虚拟网卡。DLNA 独立于 Whisper 的加密聊天会话，同一局域网内发现它的设备可以发送播放请求。

## 构建与验证

桌面播放使用 [media_kit](https://github.com/media-kit/media-kit) 和 libmpv。macOS、Windows 的平台播放库由 Flutter 依赖随应用打包，不再需要 `WHISPER_FFPLAY_PATH` 或手工安装播放器；未给移动端加入播放器运行库。首次桌面构建需要下载对应的本地播放库，锁定版本见 `pubspec.lock`，分发时应保留依赖及编解码组件的许可说明。

Linux 使用发行版的 libmpv 和 libepoxy；Debian/Ubuntu 构建需要 `libmpv-dev libepoxy-dev`，DEB 根据实际链接版本声明 `libmpv1` 或 `libmpv2`，并声明 `libepoxy0` 运行依赖。当前 AppImage 仍依赖系统提供这些库，不能视为包含全部播放依赖的独立运行包。

```sh
flutter pub get
flutter analyze
flutter test test/cast_receiver_lifecycle_test.dart test/cast_receiver_protocol_test.dart test/cast_receiver_playback_test.dart
./script/build_and_run.sh --verify
```

Windows 的对应构建命令为 `flutter build windows --debug`。协议验证应检查设备名称、播放、暂停后进度停止、继续播放不从头开始、静音期间调整音量、关闭开关时释放资源；成功启动或控制接口返回 200 不能单独证明视频已解码。

2026-09-17 已在 macOS 和 Windows 上用局域网测试视频与 DLNA 控制请求验证上述操作，并读取底层播放器确认实际进度、音量与解码尺寸；macOS 还检查了内置播放界面。此验证不能替代各手机 App 的兼容性测试。Linux 已补充构建和打包依赖，本次未完成实机播放验证。
